# Course Reflection

The most difficult concept for me in this course was understanding how to design a system that remains reliable when many people use it at the same time. I learned that a system must do more than display information correctly. It must also handle heavy traffic, protect data, and prevent conflicting actions. Database relationships, transactions, and system scaling required careful thought.

I overcame this challenge by breaking each problem into smaller steps, studying the requirements, and practising with the assignments. Building my database design helped me understand how tables and constraints protect information. The photo-sharing system design exercise also helped me think about traffic, caching, load balancing, and background processing. Working through the tasks step by step made the concepts easier to understand.

In my QuickNotes system-design capstone, I would improve the testing and documentation, particularly how the system handles failures such as network errors, repeated requests, or unsuccessful operations. Although the project received a strong score, I want to make the design clearer and more resilient, rather than focusing only on the successful user journey.

Next, I want to learn more about cloud computing, especially Microsoft Azure, deployment, monitoring, security, and scaling applications in the cloud. I also want to practise building and testing real applications so that I can turn system-design ideas into working solutions.

This course has taught me that good software design requires planning, testing, and continuous improvement.
